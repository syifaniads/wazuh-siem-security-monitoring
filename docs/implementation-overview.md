# Implementation Overview

## Context

The project implemented a centralized security monitoring environment based on Wazuh. The documented architecture combined endpoint agents, a Wazuh Manager, indexing/dashboard components, Graylog, MISP, and email-based alert notification.

## Implementation areas

### 1. Endpoint enrollment

Endpoints were connected to the monitoring environment using Wazuh agents so that system and security events could be centrally processed.

Typical validation steps included:

- confirming agent registration
- confirming connectivity with the manager
- checking the last keep-alive state
- validating that endpoint events appeared in the monitoring interface

### 2. File Integrity Monitoring

FIM was used to identify changes to monitored files and configuration areas. The final monitoring report highlighted Wazuh rules associated with registry changes, integrity checksum changes, and newly added files.

See [File Integrity Monitoring](file-integrity-monitoring.md).

### 3. Vulnerability detection

Wazuh vulnerability detection was enabled together with endpoint inventory collection. Package and system inventory information could then be compared against vulnerability information and surfaced in the monitoring platform.

See [Vulnerability Detection](vulnerability-detection.md).

### 4. Centralized log analysis

Security events from monitored endpoints were processed by Wazuh and reviewed through the dashboard. Graylog provided an additional log-management and visualization layer.

See [Graylog Integration](graylog-integration.md).

### 5. Threat intelligence

MISP was used as part of the threat-intelligence workflow, providing a place to manage indicators and contextual information about potential threats.

See [MISP Integration](misp-integration.md).

### 6. Alert notification

Email notification was configured as an additional communication path for alerts that met the configured severity threshold.

### 7. Security analysis

The monitoring results were analyzed across several categories, including:

- authentication activity
- file integrity activity
- malware/rootcheck-related events
- web-application and server alerts
- MITRE ATT&CK mappings
- compliance-oriented mappings generated by Wazuh

See [Monitoring & Security Analysis](monitoring-analysis.md).

## Evidence model

This repository uses three levels of evidence:

1. **Final implementation** — explicitly documented in the internship report.
2. **Observed monitoring results** — supported by exported Wazuh reports and analysis.
3. **Labs / experiments** — documented in internship notes but not presented here as guaranteed production deployment.

This separation is intentional so the portfolio remains technically useful without overstating the scope of the work.
